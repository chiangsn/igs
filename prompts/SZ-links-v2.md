# 後續任務：SZ — 跨國連結配合指南第二版，並陸續接上 S2–S4 的連結

> 建立：2026-11-27（S0 撰寫）
> 開場：使用者在既有的 SZ session 貼上「下一個任務：請讀 `prompts/SZ-links-v2.md`」。

## 1. 這個任務是什麼

使用者採用了 S1 對連結分類的建議，`link-typology.md` 改成了第二版。網站要配合以下變動：

- `links.csv` 新增選填欄位 `mechanism_2`；
- 新增兩種機制：`contestation`（反制與另立框架）和 `evasion`（規避與違規），共 14 類；
- `timeline.csv` 的 `country` 規定受影響地在前、外部的主要行動者在後，網站推導事件內負擔轉嫁時依賴的慣例因此正式寫進規格；
- 每個主題標完連結，都要寫一份 `data/links-caveats.md`。

接下來會陸續有四份資料交來：

- S1 依第二版補標（`prompts/S1-links-v2.md`）；
- S2、S3、S4 第一次標記跨國連結（`prompts/S2-links.md`、`prompts/S3-links.md`、`prompts/S4-links.md`）。

這個任務分兩部分：

- **A**：先把網站改成第二版的格式，現在就做；
- **B**：之後每有一個主題交來，就接上網站。

## 2. 開工前先讀

1. `link-typology.md`：第二版。重點是第 4 節的欄位、第 6 節的機制表和第 9 節「給網站」。
2. `link-typology-revisions.md`：每一項修訂的理由。
3. `CLAUDE.md`：timeline 規格的 `country` 一行，以及「跨國連結」一節。

## 3. 範圍

### A. 配合第二版（現在做）

1. **驗證**：
   - 接受新的欄位順序：`id,from_id,to_id,flow,mechanism,mechanism_2,direction,note_zh,sources`；
   - 沒有 `mechanism_2` 欄的舊檔案也要能讀，視為全部留空；
   - `mechanism` 和 `mechanism_2` 都檢查 14 類的清單，`mechanism_2` 不能和 `mechanism` 相同；
   - 問題寫進 `data-report.md`。
2. **視圖**：
   - 兩種新機制要有中文名稱，並出現在圖例和篩選器中；
   - 依機制篩選時，加一個「包含次要機制」的選項，預設不包含；
   - 連結詳情要顯示次要機制。
3. **推導的事件內負擔轉嫁**：
   - 推導規則現在有規格依據，在 `site/README.md` 註明出處是 `CLAUDE.md` 的 `country` 規定；
   - 確認推導規則的 issue 標籤可以依主題分別設定。S2–S4 的標籤和 S1 不同，例如 S2 的戰爭多半是多國事件，不一定是負擔轉嫁。所以只對 S1 開啟，其他主題等 B 階段再決定。
4. **測試資料**：可以在 scratchpad 做一份含 `mechanism_2`、`contestation`、`evasion` 的假資料測試，不要進 repo。

### B. 每有一個主題交來

使用者會告訴你哪一個主題完成了。每次都要做：

1. 重跑管線，確認 `data-report.md` 中這個主題的連結沒有錯誤，警告都已記錄。
2. 確認這個主題的「跨國連結」分頁自動出現，`links-caveats.md` 的一句話版本和「使用前請讀」都有顯示，原本的網絡圖移到「相關事件網絡」。
3. 在 `topic-config.json` 為這個主題寫 `networkNote`，說明它的 `linked_ids` 有哪些特性，內容取自這個主題的 `STATUS.md`。
4. 推導的事件內負擔轉嫁：
   - 依這個主題的 `STATUS.md` 建議，判斷要不要開啟；
   - 要開啟的話，擬定 issue 標籤和符合的事件清單，寫進 `site/STATUS.md`，**請使用者確認**後才上線。
5. 回歸檢查：其他主題的頁面不受影響。
6. commit 和 push（見第 6 節）。

## 6. 規則

- **A 部分的 git 範圍**：
  - `site/`
  - 目前已修改的共用檔：`CLAUDE.md`、`REGISTRY.md`、`狀態摘要.md`、`link-typology.md`、`link-typology-revisions.md`、`prompts/`

- **B 部分的 git 範圍**：`site/`，以及交來的那個主題的資料夾。
- **commit 前**：用 `git status` 確認沒有 `.html` 暫存檔被加入。
- **push 前先取得同意**：列出這次要 commit 的檔案清單和摘要，等使用者在對話中同意後才 push。
